# 神 AI 原脚本接入与行为核对

超人模式通过 `RulePolicy` 加载原 Lua 脚本。原包中的 20 个标准角色脚本和 7 个变体均可选择。过去的 `community_combo`、`community_guard` 是另行编写的有限规则，保留为独立基线，不代表完整神 AI。

本次迁移以行为一致为验收条件：给定相同游戏状态、脚本和随机种子，比较每一帧的方向键和六个按钮输入。胜率相近不能证明行为一致。

## 执行与信息

`policy/god/package.py` 选择脚本并解析原文件名编码；`runtime.py` 为每个策略实例创建独立 Lua 5.1 状态；`api.py` 提供脚本需要的读状态和按键函数。

`yield`、`wait` 和协程恢复以游戏模拟帧为时钟。每一帧只能推进一次。原 Windows C 运行库的随机数序列、按键队列顺序及延迟都保留。脚本执行错误会使调用失败，不能静默变成空操作。

环境每次暂停后读取双方角色、对象、碰撞框、动作、标志位、手牌、技能、角色专用状态和卡组。原脚本与学习策略使用同一份 `privileged_state` 观测。每个 32 位整数由两个数值分量表示，避免浮点转换丢失标志位或地址的低位。拟人模式继续使用其可见信息和反应延迟约束。

原程序中行为明确的特殊情况也保留，包括对角方向的释放顺序、延迟缓冲区的原有复制顺序、距离计算的单精度舍入、卡牌空槽保留上一读数，以及选中卡牌可用性的直接指针读取。不得为了代码整洁自行改变这些结果。

## 原包缺失定义的修补

用户已授权补齐缺失定义。修补只对下列 SHA256 完全一致的文件生效，原文件不改写：

`01_marisa_main_新版厨远A.ai`：`33bd3d0faf57a2a96f2b3806dbf9f4abf69e1748445cdf629991899f2fa9ec4c`。

| 定义 | 补充值及依据 |
| --- | --- |
| `wait_frame` | `1`；同包 `00_reimuEX2_main.ai` 第 193 行的初值。 |
| A 的两个距离项，动作 300、301 | 均为 0 至 160；标准魔理沙脚本第 2231 行的 A 条件为距离不超过 160，变体对这两个区间取并集。 |
| DA，动作 305 | 200 至 300；标准脚本第 2235 行。 |
| 2B，动作 402 | 150 至 300；标准脚本第 2243 行。 |
| 5B，动作 400 | 301 至 500；标准脚本第 2254 行为大于 300 且不超过 500。 |
| 6C，动作 411 | 601 至正无穷；标准脚本第 2259 行为大于 600。 |
| 空中 5C，动作 410 | 401 至正无穷；标准脚本第 2264 行为大于 400。 |

`dis` 是整数，因此严格下界可加一转换。这些距离表是依据同包标准脚本补写的定义，不是找回了该变体作者未提供的原表。变体已有的其他条件原样保留。

另一个补定义发生在 C++ 参考读取器中：原 `Obj` 构造函数未初始化四个坐标和速度浮点字段；读取过滤器拒绝负零或极小值时，会暴露未初始化内存。参考读取器明确把这四项初值设为零，并在验证报告中记录。迁移读取器采用相同初值。不能把这项修补描述为复现了未初始化内存的值。

## 验证方法与当前边界

`tests/god_reference` 从指定原 C++ 源码提取读取器和按键函数，编译为独立参考库。替换操作系统读内存入口，向两份实现提供相同字节。除前述初值修补外，碰撞框计算也按已核对的包内 0.93 行为调整，具体调整逐项写入验证报告。它不注入游戏进程。

`tests/test_god_native_reference.py` 对照 20 个角色的字段、对象、碰撞框、按键、手牌、延迟和随机数。`tests/test_god_scripts.py` 对照所有 27 个脚本在指定状态序列中的原调度器输入，并检查实例隔离。这些测试证明被覆盖分支的行为；不能替代真实对战。

`tools/validation/god_parity.py` 执行完整真实游戏回合，每帧比较原 C++ 读取器、原 Lua 调度器和迁移策略。每个案例保存配置、卡组、逐帧输入及状态摘要；失败记录准确帧数、异常和调用栈。原调度器测试使用迁移的 Python 状态接口，该接口另由 C++ 对照覆盖，因此它不是直接运行包内 `th123_ai.exe` 的端到端对照。

`tests/test_god_packaged_binary.py` 使用 Unicorn 的 x86 模拟器直接执行指定 SHA256 的包内机器码，对照坐标转换、对象返回值、可选对象、投射物距离和角色专用状态，不启动旧程序、不改写其文件。原始对象存储在测试中明确清零，避免把未初始化字节当成有效状态。测试依赖 `unicorn==2.1.4`。

输入桥接还修正了两项会改变游戏行为的问题：长按必须由原游戏解码为逐帧递增的计数，不能每帧重写为 1；角色出场阶段必须等原游戏读取输入，不能提前覆盖角色按键。两局各 600 帧的环境记录导出为官方回放后，原游戏播放的逐帧状态已通过对照。

下述真实游戏结果来自 ABI 8。当前 ABI 9 新增按座位接管输入的命令，共用已有按键处理路径；协议检查及 MSVC x86 编译已通过，真实游戏尚未复验。旧结果不作为新 DLL 已通过完整验证的证明。

按包内行为及输入时序修正后的完整回合验证，已通过灵梦标准脚本、EX1、EX2 在双方座位上的六局对照，分别为 5986/5986、5927/6110、5098/6542 帧。随后三局因用户要求停止本机弹窗验证而主动中断，不能计为通过，也不是策略差异。当前尚未达到“27 个脚本、两个座位全部通过”。离线按帧控制的证据也不能代替实时人机入口的验证。

配置入口为 `rules=god track=superhuman`。单次验证由 `config/god_parity.yaml` 组合统一配置空间，必须显式提供独立游戏目录和参考库路径。角色与卡组由环境初始化的 `episode.match.player_0`、`player_1` 选择；策略不再固定在魔理沙 1P、灵梦 2P。
