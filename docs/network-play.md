# 联网对战施工记录

联网使用两个真实游戏引擎和原游戏协议。AI 只控制自己的座位，游戏不暂停等待 Python 推理。赛制由原游戏执行，包括三局两胜、局间过渡和比赛后的菜单流程。完整验收要求见[训练与交付验收](training-acceptance.md)。

## 已实现的连接入口

`native/SokuRLBridge/NetworkStart.cpp` 在标题菜单完成展开后，通过 SokuLib 的原生连接菜单建房或加入房间。它不调用等待场景切换的阻塞函数，不控制比赛输入，不改双方角色，也不修改游戏赛制。

下列环境变量是原生模块与启动进程之间的参数，目前还不是完整的用户运行入口：

| 变量 | 含义 |
| --- | --- |
| `SOKURL_NETWORK_ROLE` | `host` 建房，`join` 加入；变量不存在时不启用此模块 |
| `SOKURL_NETWORK_PORT` | 必须明确给出 1–65535 的十进制端口 |
| `SOKURL_NETWORK_ADDRESS` | 加入时必须提供 IPv4 地址 |

网络启动与离线 `SOKURL_VS_BOOTSTRAP=1`、解除限速 `SOKURL_UNLIMITED_PACING=1` 冲突时，模块加载失败。输入错误也会直接拒绝加载。网络入口不开放旁观者。

自动连接入口明确选择本地键盘设备。它没有人工按键来设置输入设备编号，不能沿用未初始化的手柄编号。人工启动、未设置 `SOKURL_NETWORK_ROLE` 的游戏不受此设置影响。

标题就绪条件来自原版 1.10a 的 `Title::onProcess`：菜单状态非零且 `Title + 0x68C` 的菜单展开计数至少为 16，并且没有活动子菜单。只有原函数仍返回标题场景时才创建连接菜单。模块只发起一次连接；连接失败由原游戏菜单呈现，不在后台自动重试。

## 尚未完成

连接入口已通过 MSVC x86 编译及双引擎真实连接检查。单座位输入调度、联网状态采集、模型推理入口、逐局与整场比赛边界、推理超时及断线记录尚未接入，不能将此模块称为可玩的人机对战。

现有输入钩子位于 `0x40A45D`。只读反汇编确认，调用返回后原游戏从逻辑按键生成 `KeymapManager + 0x62` 的位标记。这为在网络发送前注入本地按键提供了候选位置；仍需核对联网状态下的对象归属和调用时序，不能直接套用离线覆盖双方按键的实现。

## 连接诊断结果

提交 `ffc4502` 的 DLL SHA-256 为 `812d42919987fb1cf0fce8ce5aecb9ad90a803fb7d91fd0d36e7fb35bad567c5`。独立游戏副本上的 `network-start` 诊断使用回环地址和端口 18741；两端的游戏模式分别切换为 4、5，但随后都在 `0x81FF7C` 抛出 `0xC000000D` 异常，未进入网络选人场景，120 秒连接检查失败。

只关闭该副本的 SkipIntro 后，`network-start-without-skip` 两端均停留在标题场景，120 秒内没有进入网络选人，也未观察到相同异常。这次对照没有经过相同的选人路径，不能证明关闭 SkipIntro 修复了异常。下一步需要记录标题菜单状态，并采集首次异常的调用栈，区分启动初始化、菜单调用时机与实例目录共享的影响。两次诊断均已结束，并关闭各自创建的两个游戏进程。

后续 `network-start-trace2` 采集到原生栈：`Title::onProcess` → `setBattleMode`（返回地址 `0x43EA59`）→ 输入设备容器取值（返回地址 `0x43E3DE`）→ 无效参数处理。原游戏从输入管理器的 `+0x74` 读取设备编号；自动菜单入口没有人工按键事件，编号仍为 0，访问不存在的手柄 0 时触发容器边界检查。取值函数 `0x40A8E0` 和调用方反汇编共同确认了此路径。

提交 `b730ad0` 在自动连接前将本地输入设备明确设为键盘（编号 −1）。MSVC x86 构建通过；DLL SHA-256 为 `f039c44bbca0161258d7ef48d3a92f5f7302c089c8ee51168c46d0befe858bcd`。移除临时异常记录模块后，`network-start-keyboard` 用相同双引擎流程成功进入主机选人场景 8 和客户端选人场景 9，耗时 **47.831999998539686 秒**。结果文件明确记录 `success=true`，两个自有游戏随后正常清理。该检查只证明连接及进入选人，不证明已完成战斗或整场比赛验收。
