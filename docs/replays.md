# 官方回放与环境轨迹

`src/soku_rl/replay/format.py` 已实现 th123 1.10a 官方 `.rep` 的二进制读取和写入。它保存原始头部、双方角色与外观、实际卡牌列表、其他选人字节、场景与音乐、种子，以及全部 16 位输入记录。

两份现有原游戏回放已通过读取、重新编码的逐字节对照。环境导出的两局回放也已通过原游戏播放对照：每局 600 帧，含初始帧共比较 601 个状态，双方输入、动作、位置、血量及桥接记录的其余游戏字段均一致。比较时只统一播放模式和桥接进程的局编号，再重算校验值。这两个字段不属于战斗物理状态。

验证入口为 `tools/validation/replay_parity.py`。它检查连续重置和关闭时的保存，以及原游戏对保存文件的播放结果。此项验证检查输入和回放时序，不衡量策略胜率。

## 环境自动保存

训练和评估使用 `WorkerBackend` 时，每局回放写入工作进程日志旁的 `replays/<本次连接标识>/`。文件名包含递增局号和环境槽位；同名 JSON 保存种子、帧数、结束原因和 SHA-256。

击倒、达到环境帧数上限、重置和关闭都会结束当前记录。工作进程遇到错误时，会先尝试读取并回传尚能恢复的回放，再报告错误。如果游戏进程已崩溃，尚未读取的进程内记录无法恢复，错误会明确报告。调用低层 `SokuGameBatch` 的程序须在启动游戏前执行 `enable_recording()`，并用 `take_replays()` 取走记录。

回放输入直接取自原游戏的记录队列。它保存原游戏实际读取的输入；不会把角色出场期间尚未读取的策略指令写成游戏输入。桥接调用原游戏的输入解码函数更新长按计数。

## 回放与环境轨迹互转

在 Windows 游戏运行环境中执行：

```powershell
python tools/convert_replay.py track=superhuman replay.source=episode.rep replay.game_directory=GAME_DIR output=episode.rollout.zip
```

将 `track=superhuman` 改为 `track=human`，即可使用拟人模式的观测。两种模式共用训练环境的观测读取器、编码和历史帧堆叠。转换逐帧执行，不需要训练模型。角色、卡牌、种子和场景取自回放；配置中的角色和卡组选择不会改写回放。

`replay.match_index` 选择文件中的一条对战记录，从 0 开始。转换输出该记录的第一个环境回合：从初始帧开始，遇到首次击倒、`episode.max_frames` 或回放输入耗尽时停止。因此，原文件中后续回合不会被错误地拼接为同一个训练回合。原始回放中的全部对战记录仍保存在轨迹文件中。

轨迹文件是 ZIP，包含原始 `.rep`、环境配置和逐帧 NumPy 数组。数组包含双方观测、奖励、结束状态，以及游戏处理后的八项输入计数。这些计数包含长按长度，不能直接当作离散策略动作。官方 `.rep` 不保存策略提议、推理结果或尚未生效的延迟指令；导入接口不会猜测这些数据。

`soku_rl.replay.rollout.read_rollout(path)` 逐帧读取轨迹，避免一次载入全局观测。超人观测中的对象地址属于回放进程，会随进程分配变化；回放还原的是游戏行为，不是原进程的内存地址。

重新导出官方回放不需要启动游戏：

```powershell
python tools/convert_replay.py replay.operation=export replay.source=episode.rollout.zip output=restored.rep
```

导出使用轨迹中保存的原回放字节，包括未转换为环境回合的其余记录。它不通过位置或动作编号反推输入。转换中断、缺少完整清单的轨迹不能导出为已完成记录；已存在的目标文件不会被覆盖。

回放转换使用 `config/replay_conversion.yaml`。视频渲染仍使用 `config/replay.yaml`。

## 格式依据

格式直接核对本项目支持的原游戏可执行文件，其 MD5 为 `DF35D1FBC7B583317ADABE8CD9F53B2E`。读取函数地址为 `0x42EAC0`，单条对战记录的读取函数地址为 `0x42D7F0`。原游戏文件仅被读取，没有改写。

[SokuLib 的 InputManager](https://github.com/SokuDev/SokuLib/blob/master/src/InputManager.cpp) 和本地固定版本的同名文件标识了原游戏回放读取入口。[ReplayDnD](https://github.com/SokuDev/SokuMods/tree/master/modules/ReplayDnD) 调用该入口启动回放。

| 文件部分 | 字节布局 |
| --- | --- |
| 版本 | 4 字节无符号整数，接受 `0xD2` 与 `0x100D2`。 |
| 头部 | 10 字节；第 8 个字节为对战记录数。其余字节原样保存。 |
| 每方选人数据 | 角色 1 字节、外观 1 字节、卡牌数 4 字节、每张卡 2 字节，再接 3 个原始选人字段字节。 |
| 每场设置 | 3 个单字节字段与 4 字节随机种子。 |
| 输入序列 | 4 字节记录数，随后每条记录 2 字节。 |

多字节整数使用小端序。输入的高位、记录顺序及奇数长度均原样保存；读取器不会自行补齐、删除或解释尾部记录。截断、版本不符、卡组超长及未识别的尾部数据会立即报错。

回放头中的选人字节有尚未命名的字段；代码用 `info_byte6` 表示写回原 `PlayerInfo` 第 7 个字节的值。这一名称只描述位置，不假设其游戏含义。
