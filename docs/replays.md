# 官方回放与环境轨迹

`src/soku_rl/replay/format.py` 已实现 th123 1.10a 官方 `.rep` 的二进制读取和写入。它保存原始头部、双方角色与外观、实际卡牌列表、其他选人字节、场景与音乐、种子，以及全部 16 位输入记录。

当前已经验证两份现有原游戏回放：读取后重新编码，所得字节与原文件完全相同。环境每局自动保存 `.rep`、由 `.rep` 重建环境轨迹、导出文件的原游戏播放对照仍在接入，尚不能据此宣布互转完成。

## 格式依据

格式直接核对本项目支持的原游戏可执行文件，其 MD5 为 `DF35D1FBC7B583317ADABE8CD9F53B2E`。读取函数地址为 `0x42EAC0`，单条对战记录的读取函数地址为 `0x42D7F0`。原游戏文件仅被读取，没有改写。

[SokuLib 的 InputManager](https://github.com/SokuDev/SokuLib/blob/master/src/InputManager.cpp) 和本地固定版本的同名文件标识了原游戏回放读取入口。[ReplayDnD](https://github.com/SokuDev/SokuMods/tree/master/modules/ReplayDnD) 调用该入口启动回放。

| 文件部分 | 字节布局 |
| --- | --- |
| 版本 | 4 字节无符号整数，接受 `0xD2` 与 `0x100D2`。 |
| 头部 | 10 字节；第 8 个字节为对战记录数。其余字节原样保存。 |
| 每方选人数据 | 角色 1 字节、外观 1 字节、卡牌数 4 字节、每张卡 2 字节，再接 3 个原始选人字段字节。 |
| 每场设置 | 3 个单字节字段与 4 字节随机种子。 |
| 输入序列 | 4 字节记录数，随后每条记录 2 字节。 |

多字节整数使用小端序。输入的高位、记录顺序及奇数长度均原样保存；读取器不会自行补齐、删除或解释尾部记录。截断、版本不符、卡组超长及未识别的尾部数据会立即报错。

回放头中的选人字节有尚未命名的字段；代码用 `info_byte6` 表示写回原 `PlayerInfo` 第 7 个字节的值。这一名称只描述位置，不假设其游戏含义。
