# 同一 PPO 的跨对手角色开发诊断

目前长预算主要训练魔理沙对灵梦神 AI，不能由单角色结果证明通用 BR。
新增 `benchmark_address_cross_character`，复用原 `tools/benchmark_br.py`，
冻结原 BC 和慢反馈 1,048,576 步模型，分别对角色编号 1、2、5、6 的原神 AI
执行两世界 × 双座位，各 16 局，共 32 局。角色 0 的已有灵梦测评单独保留。
所有角色和座位使用同一份学习策略，不重训、不增加角色专用网络或规则。

两个模型使用完全相同的世界、角色、逻辑对手名及 common_roles 策略种子；
每个角色仅四局，作为开发范围诊断，不能据少量胜局宣称跨角色强度已达标。
选择的两世界沿用已有开发种子，不称为独立测试。完整原神 AI、不掺 uniform，
旧 `.dev/game` 模块、逐帧完整观察与全部 576 动作均保持。实际角色设置来自
测评计划，不能把被测模型的原训练对手灵梦配置继续用于其他角色。

先通过共享策略加载和配对计划预检：模型身份、完整输入/动作、学习者角色 1、
四种对手、每角色每座位两个世界及双方实际随机种子均核对，再提交启动。
调度器等待慢反馈最终纯神 AI 与固定 .5 对照完成核对、私有 worker 清理，
随后在其释放的空闲 GPU 0 顺序评估 BC 和最终 PPO，为长片段后续测评保留
GPU 7；不与这两项最终测评叠加更多游戏负载。
两组都执行完整计划，不根据前四局成绩提前筛掉或增加样本。

结果须逐角色、逐座位报告胜/负/超时、双方掉血与符卡动作；核对原始回放、
模型/源码/游戏模块身份、实际角色和策略种子及正常清理。不反馈训练课程，
不将它用作示范或在线训练数据。此项扩大的是验证范围，不替代尚未达标的
灵梦 BR，也不改变正在运行的均衡座位和长片段训练预算。

共享入口预检已通过：真实加载原 BC（零 PPO 步）与最终 1,048,576 步模型，
检查点 SHA256 分别仍为 `5a3ba7e…` / `c059a2c…`；两者完整契约相同，
同一策略对象用于双座位及四种对手。正式配对函数生成每模型 16 局计划，
全部实际世界/双方策略种子、角色及座位逐项一致。四个原神 AI 策略也通过
正式加载入口构造，无噪声包装。证据
`logs/diagnostics/address-cross-character-preflight-20261003/summary.json`，
脚本/日志 `.dev/check-address-cross-character-20261003.{py,log}`。
该预检不启动游戏，不是跨角色实战成功的证据。
