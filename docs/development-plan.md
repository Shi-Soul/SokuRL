# 开发计划与验收顺序

公共双人环境、学习包装以及 PPO、IPPO、NFSP、PSRO 适配已经存在。接下来的工作围绕合并后的运行正确性、策略强度和联网对战展开，不再把训练接口列为尚未实现。

- [环境建模](environment-model.md)定义观测、动作、时序、奖励和结束条件。
- [训练算法](algorithms.md)说明学习路径、产物和限制。
- [环境验收记录](env-validation.md)保存具体版本、命令、结果和失败原因；[交付清单](training-acceptance.md)规定最终通过条件。

## 1. 验证合并后的 ABI 8

ABI 8 合并了有符号灵力字段和保留进程的对局重置。先核对 Python、DLL、配置和原始游戏身份，再完成逐帧控制、连续重置、状态及图像同步验证。

通过条件：同一种子和完整输入序列可复现；重置后帧号、历史与按键队列正确；多实例互不影响；没有丢帧；异常只关闭本任务拥有的实例。旧 ABI 7 的轨迹不能代替本次验收。

## 2. 完成训练与独立评测

分别推进固定规则对手训练和双人学习。训练记录包含完整配置、模型身份、采样决策数、更新与对局结果。按相同赛道、观测和控制限制，与规则策略池对战。

模型选择使用验证集；配置固定后再使用独立测试集。15 个对手、32 个世界种子与交换座位组成每组 960 局。胜、负、同时击倒、超时和错误分别统计。当前交付要求是每条赛道至少击败 8 个对手，具体判定见[学习包装层的验收说明](learning-wrappers.md)。

通过条件：完整运行成功，最终模型能按保存配置加载，完整评测满足要求，动作回放能由真实引擎复现。损失下降或模型参数变化只能证明执行了优化。

## 3. 校准拟人观测

用不同角色、姿态、天气和遮挡的真实画面对照结构化观测。当前轮廓是近似几何，缺少绘制顺序；可见姿态和卡牌界面信息仍需补齐。

通过条件：逐项说明保留、隐藏和量化的字段，记录与画面的误差，评估接口不向策略泄漏诊断信息。比较包装层时保持对手、预算和种子划分一致。

## 4. 整理运行层依赖

将被验收脚本和正式运行共用的启动、等待、记录读取逻辑移入明确命名的模块。每次只迁移一项职责，先提交可审查改动，再验证行为。

通过条件：运行代码不再反向导入验收脚本；原有入口和协议保持兼容；完整对局与错误清理继续通过。不要在一次整理中同时拆原生大文件、改协议和重写训练循环。

## 5. 实现联网人机对战

人类与 AI 各运行一个引擎，通过原游戏网络协议连接。AI 使用拟人观测与控制约束，可加载学习策略或规则策略。

通过条件：AI 只控制自己一方；联网时不暂停游戏等待推理；记录观测帧、计划执行帧和实际执行帧；推理超时与断开连接有明确处理。离线双人逐帧接口不能直接视为已经完成的联网接口。

## 协作与证据维护

仍在施工的源码、运行配置和训练进程由原任务继续管理。整理工作使用独立分支，每个提交只承担一类改动。合入前检查与继续开发分支的差异；不能用整理分支覆盖后续修复或训练记录。

设计文档描述当前接口，验收文档保留具体运行事实。历史速度、旧协议记录和中途模型结果应保留其版本与条件，不能写成当前版本的无条件能力。
