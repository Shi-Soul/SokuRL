# 训练和测评中的实际逻辑输入统计

[最终模型的回放诊断](br-input-behavior.md)显示，较易对手上的胜率恢复仍可能
伴随高度集中的方向和按键。环境现按实际成功推进的每一帧统计双方逻辑输入，
在终局 `info.input_metrics` 保存命令直方图、帧数及相邻帧命令变化次数。
同一统计覆盖单实例和向量环境；包括延迟期间的中立输入、跨决策帧的保持、
局末不足一个决策周期的帧数，局间不连接变化计数。每局独立重置。

记录的输入是延迟队列实际交给游戏的完整逻辑命令，方向采用屏幕绝对坐标。
不是成功攻击、实际位移、命中数或符卡使用数。符卡动作进入次数继续单独
来自原有战斗状态统计，仍不能解释为确认消耗符卡或确认造成伤害。
统计不进入策略观察、奖励或课程反馈，不改变控制频率和完整 576 动作空间。
逐帧仅累加两个命令计数；到终局才编码直方图，避免每帧复制完整分布到 info。

BR 和共享 PPO 的 `progress.json` 逐局保留原始计数，`input_summary` 保存
全程汇总；`episode_summary` 的座位/对手/角色分组也含 `inputs`。
CSV / TensorBoard 的 `inputs/` 记录本 rollout 完成局的双方攻击键、符卡键、
切卡键、左/右/水平中立及全中立输入比例、最常用命令占比、平均连续段长度
和输入切换率。无完成测量局时清空旧标量，缺失数据不记作零。

比例按累计帧数加权；切换率分母为各局 `frames - 1` 之和，平均连续段长度
为总帧数除以变化次数加测量局数。最常用命令占比来自所汇总对局合并后的
命令直方图，不是网络条件分布的最大概率；不同长度对局权重也不同。
只有单帧对局时没有相邻帧，省略切换率。旧日志缺少这项测量时仍可汇总，
并显式报告测量局数；损坏的帧数、命令或计数则立即报错。

正式测评逐局保存 `input_metrics_by_seat`，BR 报告按真实学习者座位汇总，
同时在 `by_opponent_and_seat` 分组内保存输入统计。旧模型仍使用同一推理
入口；已经运行中的进程不会自动获得新增日志，也不为补日志重启其训练。

29 项相关检查通过（15.75 秒），包括全部 576 命令、双座位交换、延迟/保持、
局末截断、局部重置、缺失测量、损坏输入、日志清空、BR 分组及共享 PPO。
日志 `.dev/pytest-input-metrics-20261003.log`。
全量回归为 1457 passed、12 skipped、1 deselected、30 warnings、2 subtests
passed（160.12 秒），日志 `.dev/pytest-input-metrics-full-20261003.log`。
实机诊断配置 `profile_input_metrics` 使用新初始化策略、双实例均衡座位、
每局 256 帧、共 1024 样本；计划把四局日志与工作进程实际接收的命令逐帧比较，并核对
PPO 更新、源码、CUDA 和私有 worker 清理。此时尚未完成实机验证，也不把
短局胜负作为强度结果。
