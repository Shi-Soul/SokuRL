# 训练与交付验收

本清单对应用户扩展后的完整目标。写完适配代码、通过替代后端检查或完成一次参数更新，都不代表全部目标已经完成。

## 必须交付

1. 原生桥接与 Python 分层：单局双人 PettingZoo `ParallelEnv` 是公共接口，多局执行复用相同规则。
2. 图像与结构化状态两种观测。结构化状态允许读内存，但必须限制可见性和精度。两种观测都遵守每 3 帧决策、5 帧感知到按键延迟，参数可配置。
3. TorchRL、BenchMARL、OpenSpiel PSRO 和 NFSP 适配。可以根据同时行动、多个对局和真实游戏进程调整实现，不能把其他库的 NFSP 当作 OpenSpiel 接入结果。
4. 在服务器完成完整对局、连续重置、多局并行、生态接口检查。记录实际命令、配置、版本、结果与错误。
5. 运行基础训练并初步调参。记录采样量、更新次数、损失、参数变化、对局结果；不能仅用损失下降证明策略变强。
6. 获得有意义的可玩策略，保存模型及加载入口。用保留的评估种子，与已有规则策略对战，并分别统计胜、负、双重击倒和超时。
7. 保存动作回放及重放入口，录制真实游戏回放视频。记录起始配置和随机种子；原生 `.rep` 若不可用，必须明确说明所交付回放格式与局限。
8. 检查模块职责和接口，更新使用文档，清理本次临时调试文件。

## 对战结果必须说明的条件

用户明确要求下列三个运行场景，均属于最终交付范围：

| 场景 | 学习策略与规则策略的共同限制 | 运行方式 |
| --- | --- | --- |
| 拟人赛道 | 受限观测；默认每 3 帧决策，动作延迟 5 帧；双方使用相同配置 | 离线双人环境，可暂停并批量推进 |
| 超人赛道 | 逐帧决策；允许指定的内存状态；双方使用相同配置 | 离线双人环境，可暂停并批量推进 |
| 联网人机对打 | AI 使用拟人赛道的观测及控制限制；同一策略接口可加载学习策略或规则策略 | 人和 AI 各启动一个游戏引擎，使用游戏网络对战连接 |

两个评估赛道分别记录策略版本、输入字段、决策间隔、延迟、角色、位置、种子和结果，不能合并为一个未标明条件的胜率。策略的观测空间属于模型格式的一部分，不能把仅接受拟人观测的模型直接解释为使用全内存状态的模型。

联网运行不能暂停游戏来等待 Python。它需要记录感知帧、请求执行帧、实际执行帧及推理超时；远端玩家的按键由原游戏网络协议接收，不得通过 AI 接口覆盖。联网运行与离线推进共用观测过滤和控制约束，但使用不同的引擎运行模块。

联网比赛遵守原游戏赛制，包括三局两胜及局间过渡。一方血量归零不能直接作为整场比赛结束：必须区分单局结果、双方已赢局数、下一局开始和整场比赛结束。局间释放 AI 按键并清除上一局待执行动作；新局按模型训练时的初始规则重建观测历史和策略记忆。比赛结束后回到原游戏结果及选人流程，连接仍由原游戏管理，不能由单局训练环境自动重置或关闭。验收必须覆盖至少一场打满三局的比赛、结束后再开始一场比赛，以及主动断线。

已有规则策略读取过内部动作编号，并曾使用逐帧即时控制。新策略采用受限观测和控制延迟。评估必须写明规则对手是否保留旧权限，不能将不同权限的对局描述成同条件对比。

同条件规则对手需要适配受限观测。依赖被移除字段的规则必须明确修改或禁用，不能用伪造的动作编号冒充输入兼容。旧权限规则对手可以保留为另一个评估组，其结果应独立报告。

训练种子和评估种子分开；两个玩家位置分别评估。超时必须单列。有限时长训练可显式使用超时零收益，但这不等于证明实际游戏发生平局。

## 后续施工顺序

用户指定先完成全部功能和交付，再优化 PSRO 与 NFSP。已经运行的正式训练、评测和验证继续执行；在下列功能缺项完成前，不新增以调参为目的的训练。

1. 补齐联网人机对战。实现原游戏协议的连接入口、只控制本地座位的按键路径，以及不暂停游戏的观测与推理流程。复用公开观测、模型加载和控制配置。用两个真实引擎验证双方状态一致、远端输入不被覆盖、断线处理和超时记录。现有离线桥接不能直接作为完成证据。
2. 完成环境验收。收齐图像连续重置结果，检查状态与图像两种模式、单实例与多实例、PettingZoo、TorchRL 和 BenchMARL 的完整结果。每项结果关联代码版本和配置。
3. 完成训练产物交付。保留固定规则对手训练与学习策略互打两条路径；验证 PSRO 种群和 NFSP 平均策略可独立加载，记录双座位更新及完整训练结果。中途检查点与成功完成的训练分别标记。
4. 完成两条赛道的规则评测和独立测试。每条赛道的验证集及独立测试集各 960 局，覆盖 15 个非空闲规则、32 个种子和两个座位。每个规则的胜率分母包含超时局；超过 50% 胜率的规则至少达到 8 个，才满足该赛道的既定验收标准。未完成的评测不得提前判定达标。
5. 整理可玩策略、动作回放、原生回放说明、视频和复现入口，清理本次临时文件。完成上述功能及交付检查后，再根据完整评测结果优化 PSRO 和 NFSP；若策略强度未达标，继续训练和评测，不能降低验收标准。
