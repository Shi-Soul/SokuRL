# 暂停帧内的牌组指针读取

完整快照已通过[实际对局等价验证](offline-native-snapshot.md)。在既有 4096 步
父/子 cProfile 中，worker 的 `PrivilegedReader.deck` 调用 8208 次，累计
2.555 秒；整个 worker privileged 解码 5.830 秒。牌组是其中的一部分，不能
把嵌套累计时间相加或由局部计时直接推算总体加速。

原读取遍历全部 20 张有效牌，每张牌都重新读取其所在内存块的表项。相邻牌
共享一个 8 张牌的块，所以同一暂停状态下存在重复指针读取。新实现只在本次
`deck` 调用内复用已经读到的表项；20 个牌值仍全部读取，下一帧、下次调用均
重新读取表项及牌值，没有跨帧缓存，没有删除完整状态字段或改变索引运算。
它同时用于旧 ProcessMemory 和不可变 SnapshotMemory，不需要新 DLL。

针对性检查为 188 passed、1 skipped（5.86 秒），日志
`.dev/pytest-privileged-deck-20261003.log`。新增检查覆盖双座位、不同块数、块
边界及环形起点、uint32 大计数器、unsigned short 牌值、下一帧换指针/值、
未捕获牌值和非法头部；既有原生捕获/原读取器对照也通过。没有扩大内存读区间，
逐张两字节捕获仍可用。

真实诊断 `profile_native_deck_verification` 在每次实际牌组读取后另执行原来的
逐标量算法并比较，再用既有快照 worker 对照同一暂停帧的完整状态和双视角
编码。固定 4096 步、8 环境、全部观测动作及原 God/PPO；初始化和 2048/4096
步参数/Adam须与旧快照诊断逐位相同。验证程序的额外重复工作不用于计时。
之后在同一空闲 GPU 5 顺序运行 `profile_native_deck_control` 和原
`profile_native_snapshot`，分别使用独立诊断入口保留的旧逐标量遍历和新实现，
两者均不带额外核对。保留父/子 pstats 和相同检查点比较；结果未完成前不宣称
吞吐改善。这减少设备差别，仍是共享节点各一次短运行，不保证其他负载下收益。

当前两个长训练的 worker 在改动前已经加载原读取器；不更换其进程、配置或
实验预算。后续新启动进程记录新的 Python 源码身份，游戏模块身份不变。
